# 缠论集成到技术分析 — 工作分解与实施规划

> 版本: v0.3.0 规划 | 日期: 2025-06-16
> 基于：缠中说禅原文 (chzhshch.blog)，第 17/18/20/21/22/24/25/32/33/35/43/44/65/67/71 课

## 一、背景与目标

### 1.1 现状
当前 `market_analyst`（技术分析师）Agent 使用传统西方技术指标（SMA/EMA/MACD/RSI/BOLL/ATR/VWMA/MFI），通过 `stockstats` 库计算。这些指标是**或然率**层面的辅助工具，缺乏缠论基于**几何递归**的绝对性分析框架。

### 1.2 目标
将缠论核心算法嵌入技术分析数据层，使 `market_analyst` Agent 能够获取缠论分析结果（中枢、买卖点、背驰判断），输出与现有指标互补的缠论视角技术报告。

### 1.3 设计原则
1. **严格遵守缠论原文定义** — 所有算法以原文的几何定义为标准，不做"简化"或"改良"
2. **纯数据层实现** — 缠论计算在 `dataflows` 层完成，返回结构化文本结果，不侵入 Agent 层
3. **渐进式集成** — 分 4 个 Phase 交付，每个 Phase 独立可用
4. **不破坏现有功能** — 所有现有指标继续可用，缠论作为新增工具接入

## 二、缠论核心概念体系（算法映射）

以原文定义为基准，将缠论理论分解为可实现的算法模块：

```
K线 → 包含处理 → 分型 → 笔 → 线段 → 中枢 → 走势类型 → 背驰 → 买卖点
```

| # | 概念 | 原文定义 | 算法输入 | 算法输出 | 对应原文课程 |
|---|------|----------|----------|----------|-------------|
| 1 | K线包含处理 | 向上时取 max(low), max(high)；向下时取 min(low), min(high) | 原始OHLCV | 处理后K线序列 | 第65课 |
| 2 | 分型（顶/底） | 三根K线：顶分型 g1>g2 且 d1>d2 且 g3>g2 且 d3>d2；底分型反之 | 处理后K线 | 顶/底分型标记 | 第65课 |
| 3 | 笔 | 顶底交替连接，顶底间至少1根独立K线 | 分型序列 | 笔序列(起终点、方向) | 第65课 |
| 4 | 线段 | 特征序列分型判定（第一种/第二种情况） | 笔序列 | 线段序列(起终点、方向) | 第67/71课 |
| 5 | 中枢 | 至少三段连续次级别走势类型的重叠区间 | 线段序列或走势类型 | 中枢[ZG, ZD, GG, DD, 起止时间] | 第17/18课 |
| 6 | 走势类型 | 盘整(1个中枢)、趋势(≥2个不重叠同向中枢) | 中枢序列 | 走势类型(方向、级别、起终点) | 第17/18课 |
| 7 | 背驰 | MACD辅助(黄白线回拉0轴+柱子面积对比)+区间套 | 走势类型、MACD数据 | 背驰标记(级别、类型、位置) | 第24/25/43课 |
| 8 | 买卖点 | 一买(趋势底背驰)、二买(一买后次级别回抽)、三买(中枢上回试不破ZG) | 背驰+中枢+走势类型 | 买卖点(类型、级别、位置、时间) | 第20/21课 |
| 9 | 级别递归 | 1分钟→5分钟→30分钟→日线→周线→月线 | 多级别分析 | 多级别分析结果 | 第33/35课 |

## 四、Phase 分解

### Phase 1: 基础层 — K线处理 + 分型 + 笔（~3天）

**目标**：实现缠论最底层的三个计算模块，可通过单元测试验证正确性。

**文件**：
| 文件 | 内容 |
|------|------|
| `chanlun/types.py` | 数据类型：`KLine`, `ProcessedKLine`, `Fractal`(顶/底), `Stroke`(笔) |
| `chanlun/core.py` | `process_inclusion()` 包含处理 + `find_fractals()` 分型识别 + `identify_strokes()` 笔划分 |
| `tests/test_chanlun_core.py` | 覆盖原文典型场景的单元测试 |

**算法细节**：

#### 4.1.1 K线包含处理（严格按第65课）
```
输入: 原始K线序列 [(date, open, high, low, close, volume), ...]
处理: 从左到右遍历
  - 记录前一根K线方向（由更前一根的比较确定）
  - 当 K[i] 与 K[i-1] 存在包含关系 (K[i].high >= K[i-1].high 且 K[i].low <= K[i-1].low 或反之)
    - 向上时: 合并为 (max(h1,h2), max(l1,l2))
    - 向下时: 合并为 (min(h1,h2), min(l1,l2))
  - 合并后的K线继承前一根的时间标记
  - 严格顺序原则：先处理1-2，再用合并结果与3比较
输出: 处理后K线序列（无包含关系）
```

#### 4.1.2 分型识别（第65课）
```
输入: 处理后K线序列
处理: 三根一组
  - 顶分型: K[i-1].high > K[i].high 且 K[i-1].low > K[i].low 且 K[i-1].high > K[i+1].high 且 K[i-1].low > K[i+1].low
  - 底分型: K[i-1].high < K[i].high 且 K[i-1].low < K[i].low 且 K[i-1].high < K[i+1].high 且 K[i-1].low < K[i+1].low
输出: 分型序列 [(date, type=TOP/BOTTOM, value), ...]
```

#### 4.1.3 笔划分（第65课）
```
输入: 分型序列
处理:
  - 顶底交替：连续同类型分型只保留极值那个
  - 笔的构成：先顶后底 → 向下一笔；先底后顶 → 向上一笔
  - 特殊情况：两顶/底之间没有其他底/顶 → 忽略前一个
输出: 笔序列 [(start_date, end_date, direction=UP/DOWN, start_val, end_val), ...]
```

**测试场景**：
- 简单上升K线 → 无顶分型 → 无笔
- 典型顶分型（三根K线 middle < left 且 middle < right）→ 识别
- 包含关系处理：向上序列中的包含 → 取高高；向下序列 → 取低低
- 连续包含：5根K线连续包含 → 逐步合并
- 笔划分：交替顶底 → 正确连笔
- 独立K线要求：顶底之间至少1根独立K线

### Phase 2: 中枢层 — 线段 + 中枢 + 走势类型（~4天）

**目标**：实现中枢计算，输出中枢位置和走势类型判断。

**文件**：
| 文件 | 内容 |
|------|------|
| `chanlun/segment.py` | 线段划分（特征序列 + 两种情况） |
| `chanlun/pivot.py` | 中枢识别 + 走势类型划分 |
| `tests/test_chanlun_segment.py` | 线段划分测试 |
| `tests/test_chanlun_pivot.py` | 中枢和走势类型测试 |

**算法细节**：

#### 4.2.1 线段划分（严格按第67/71课）
```
输入: 笔序列 S1X1S2X2...SnXn（向上笔开始为例）
处理:
  1. 构造特征序列: 对于向上笔开始的线段，特征序列 = X1,X2,...,Xn（向下的笔序列）
  2. 特征序列包含处理: 同K线包含处理逻辑，处理特征序列元素间的包含
  3. 在标准特征序列中找顶分型：
     - 第一种情况: 分型第1、2元素间无缺口 → 线段在该顶分型高点结束
     - 第二种情况: 分型第1、2元素间有缺口 → 需要从该高点向下的笔序列
       的特征序列出现底分型，线段才在该顶分型高点结束
  4. 前三笔必须有重叠部分，否则不构成线段
输出: 线段序列 [(start, end, direction, segments_count), ...]
```

#### 4.2.2 中枢识别（第17/18课）
```
输入: 线段序列（作为次级别走势类型）
处理:
  - 取前三个连续次级别走势类型 A, B, C
  - 中枢区间 ZG = max(A.low, B.low, C.low), ZD = min(A.high, B.high, C.high)
  - 如果 ZG < ZD → 无重叠，不构成中枢
  - GG = max(A.high, B.high, C.high), DD = min(A.low, B.low, C.low)
  - 中枢延伸：后续走势与中枢区间有重叠则延续
  - 中枢扩张：围绕新中枢的波动与围绕前中枢的波动重叠 → 更大级别中枢
输出: 中枢序列 [(ZG, ZD, GG, DD, start_date, end_date, level, is_extending), ...]
```

#### 4.2.3 走势类型判断（第17/18课）
```
输入: 中枢序列
处理:
  - 盘整: 只包含1个该级别中枢
  - 上涨趋势: ≥2个同向(向上)中枢，且中枢间无重叠
  - 下跌趋势: ≥2个同向(向下)中枢，且中枢间无重叠
输出: 走势类型 [(type=CONSOLIDATION/UPTREND/DOWNTREND, start, end, pivots), ...]
```

**测试场景**：
- 线段: 正常交替笔序列 → 特征序列分型 → 正确断段
- 线段: 第一种情况（无缺口）→ 直接确认
- 线段: 第二种情况（有缺口）→ 需辅助底分型确认
- 中枢: 三段重叠 → 确认 [ZG, ZD]
- 中枢: 三段不重叠 → 不构成中枢
- 走势: 2个不重叠同向中枢 → 趋势
- 走势: 1个中枢 → 盘整
- 中枢延伸: 第4段触及中枢区间 → 延续

### Phase 3: 交易层 — 背驰 + 买卖点（~3天）

**目标**：实现背驰判断和三类买卖点识别，这是缠论交易的核心输出。

**文件**：
| 文件 | 内容 |
|------|------|
| `chanlun/divergence.py` | 背驰判断（趋势背驰、盘整背驰、MACD辅助） |
| `chanlun/buy_sell_points.py` | 三类买卖点识别 |
| `tests/test_chanlun_divergence.py` | 背驰测试 |
| `tests/test_chanlun_buy_sell.py` | 买卖点测试 |

**算法细节**：

#### 4.3.1 背驰判断（第24/25/43课）
```
输入: 走势类型序列 + MACD数据（12,26,9参数）
处理:

A. 趋势背驰:
   - 条件: 两段同向趋势A、C，中间由B（盘整或反向趋势）连接
   - MACD辅助判断:
     1. 黄白线（DIF/DEA）从0轴远离后回拉
     2. C段对应的MACD面积 < A段对应的MACD面积
     3. C段末尾柱子缩短
   - 趋势背驰必然导致回跌到B段中枢

B. 盘整背驰:
   - 条件: 盘整中枢内的次级别走势对比
   - 三种情况:
     1. 中枢上: 脱离后回抽力度弱 → 可能形成第三类买点
     2. 中枢中: 震荡平衡态
     3. 中枢下: 跌破后回抽力度弱 → 可能形成第三类卖点

C. 区间套:
   - 从大级别逐步缩小到小级别确认背驰
   - 本级别进入背驰段 → 次级别找背驰点 → 再次级别确认
输出: 背驰标记 [(type=TREND/PATTERN, direction=TOP/BOTTOM, level, position, strength), ...]
```

#### 4.3.2 三类买卖点（第20/21课）
```
输入: 背驰标记 + 中枢序列 + 走势类型
处理:

买点:
  - 一买: 下跌趋势底背驰点 — 绝对安全，趋势必然转折
  - 二买: 一买后次级别回抽低点 — 一买后只可能是盘整或上涨
  - 三买: 次级别离开中枢后回试不破ZG — 中枢扩张或新生

卖点:
  - 一卖: 上涨趋势顶背驰点
  - 二卖: 一卖后次级别回抽高点
  - 三卖: 次级别离开中枢后回试不破ZD

特殊: 二买三买重合 → 强上涨信号（第21课94年325点案例）
输出: 买卖点 [(type=1ST_BUY/2ND_BUY/3RD_BUY/..., level, position, date, confidence), ...]
```

**测试场景**：
- 趋势背驰: A段MACD面积大、C段面积小 → 背驰确认
- 盘整背驰: 中枢内次级别走势力度递减 → 盘整背驰
- 一买: 下跌趋势最后一个中枢后出现底背驰 → 识别
- 二买: 一买后回抽 → 识别
- 三买: 离开中枢后回试不破ZG → 识别
- 区间套: 大级别背驰段 + 小级别背驰点 → 多级别确认

**集成细节**：

#### 4.4.1 多级别分析（第33/35课）
```
流程:
  1. 获取多级别K线数据（5分钟、30分钟、日线）
     - mootdx 支持分钟级K线：category=0(5分钟), category=1(15分钟), category=8(30分钟)
  2. 每个级别独立运行: 包含处理→分型→笔→线段→中枢→走势类型
  3. 级别递归确认:
     - 9段1分钟走势 = 3段5分钟中枢 = 1段30分钟中枢的成分
  4. 多级别联立:
     - 找出各级别当前处于什么走势类型
     - 各级别的买卖点是否共振
输出: MultiLevelAnalysis 对象
```

#### 4.4.4 market_analyst.py 更新
在 system_message 中增加缠论指引段落：
```
缠论分析（可选高级分析工具）：
- 调用 get_chanlun_analysis 获取缠论视角的分析结果
- 缠论核心概念：
  - 走势必完美：任何级别的趋势终将完成
  - 中枢：至少三段连续次级别走势的重叠区间，定义 [ZG, ZD]
  - 三类买点：一买(趋势底背驰)、二买(一买后回抽)、三买(离开中枢后回试不破ZG)
  - 三类卖点：一卖(趋势顶背驰)、二卖(一卖后回抽)、三卖(离开中枢后回试不破ZD)
  - 背驰：MACD辅助判断，黄白线回拉0轴+面积对比
- 缠论买卖点与传统指标信号互为验证，不一致时需仔细分析原因
```

#### 4.4.5 输出格式示例

## 五、数据获取策略

### 5.1 日线级别为主（v0.3.0）

v0.3.0 仅支持日线级别缠论分析，不涉及分钟级K线。原因：
- 缠论日线级别分析已能满足中线交易决策需求
- 分钟级数据量大且对数据完整性要求极高，后续版本再实现
- 日线数据源稳定（mootdx TCP + 新浪 HTTP 双通道），获取成本低

### 5.2 日线数据本地缓存增强

缠论需要**充足的历史数据**才能正确识别中枢和走势类型（至少需要2-3年的日线数据）。
当前 `_load_ohlcv_astock` 仅缓存 800 根K线（~3年），且缓存策略简单（当日有效）。

**增强方案**：

| 属性 | 当前 | 增强后 |
|------|------|--------|
| 数据量 | 800根（mootdx offset=800） | 5000根（新浪 datalen=5000，覆盖上市至今） |
| 缓存策略 | 当日有效，隔日重拉 | 增量更新：本地缓存 + 每日追加新数据 |
| 缓存文件 | `{code}-astock-daily.csv` | `{code}-astock-daily.csv`（兼容） |
| 数据源 | mootdx 优先 → 新浪 fallback | **新浪优先**（支持 datalen=5000） → mootdx fallback |
| 缓存格式 | CSV | CSV（兼容），新增 `_meta.json` 记录最后同步时间/行数 |

## 六、风险与注意事项

### 6.1 算法精度
- 缠论的线段划分在**第二种情况**下存在**多义性**，需严格按第71课的"当下判断"逻辑实现
- 特征序列的包含处理中，跨越两个特征序列的元素不能做包含处理（第71课强调）
- 本质上，线段划分是**唯一的**，因为所有歧义都能通过严格的定义消除

### 6.2 性能
- 分钟级K线数据量大，500条5分钟K线的笔划分应在 <100ms 完成
- 中枢递归最多到日线级别（4级），O(n) 线性复杂度
- 缓存策略：分钟级数据当日缓存，日线数据同现有逻辑

### 6.3 与传统指标的互补性
- 缠论买卖点 ≠ 传统指标信号，不一致时为正常情况
- Agent system_message 中明确要求：缠论信号和传统指标信号互为验证
- 不用缠论替代现有指标，而是**补充**新维度

### 6.4 兼容性
- `get_chanlun_analysis` 只在 `a_stock` vendor 下实现（因为依赖 mootdx 分钟K线）
- alpha_vantage / yfinance 不提供分钟级A股数据，无对应实现
- 当 vendor 非 a_stock 时，`get_chanlun_analysis` 不可用（Agent 会 fallback 到传统指标）
